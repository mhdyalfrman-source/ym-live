Connection and delivery model

Connect with a Socket.IO client compatible with the Node server, using the normal /socket.io/ path. The shipped server listens over HTTP behind your reverse proxy. PHP publishes envelopes to Redis channel update; Node dispatches their msg as a Socket.IO payload. Clients do not receive the Redis envelope.

{"channel":"room","event":"roomMessage","id":7,"rid":null,
 "msg":{"type":"normal","text":"Hello","msg":"","person":{"uid":42}}}

Routing: user + id goes to user:{id}; room + positive id goes to room:{id}; room + id=0 goes to the shared room channel; app goes to app. The user's PHP enterRoom event is intercepted by Node to join the socket and broadcast the arriving user to room listeners.

Transport caveat in the supplied Flutter source: controllers/socket_manager.dart constructs http://$ip:$port. Setting port 443 does not turn that string into HTTPS/WSS. A TLS-only deployment must update that client URL construction to use HTTPS, then test the release build. Do not weaken iOS transport security to work around it. The example below explicitly uses HTTPS.

No custom event uses an acknowledgement callback. Confirm a mutation using its PHP response; events can be missed while disconnected. Do not assume replay, ordering across PHP requests, or a durable queue. GamePix uses HTTP catalogue/configuration requests and an embedded WebView, with no dedicated game socket events; see GamePix setup.

Client → server events

Event Payload and example When / result
conn token:string required; apiKey:string required; prefix:string optional (compatibility, unused by server); user:object optional (alias fullUser); rid optional but avoid it in this version. 
{"token":"SESSION_TOKEN","apiKey":"YOUR_API_KEY","prefix":"tomchat"}
 Emit after each transport connection. Looks up the PHP token in Redis; joins user:{uid} and app. Replies appCon=1 or loginFailed. The optional rid branch currently calls joinRoom without user and can throw; enter via PHP after authentication.
joinRoom rid:int/string required (alias room); user:object required by the implementation. 
{"rid":7,"user":{"uid":42,"name":"Demo"}}
 After conn. Joins room:{rid} and room, updates Redis presence, broadcasts enterRoom. This is socket membership, not room-password/ban authorization. Prefer PHP live/enterRoom, which supplies the validated entry payload. Do not call both and count duplicate arrival events.
leaveRoom rid:int/string optional, defaults to last joined room. 
{"rid":7}
 Removes socket channel membership/presence. No explicit response event. Also POST live/leaveRoom to update database membership/seats. A PHP leave alone does not call Node's leaveRoom handler.
disconnect (transport lifecycle) No application payload to send. Close/disconnect the Socket.IO client; Node removes its tracked presence. An abrupt process failure is not guaranteed to execute cleanup. This is not a custom business event.

loginSuccess is an internal Node EventEmitter event, not a wire event. Do not wait for it on the client. There are no server socket.on handlers named sendGift, seatTake, seatMic or sendMessage.

privateMessage variants

{"type":"message","chat_id":8,"message":{"id":10,"chat_id":8,"uid":42,"content":"Hello"}}
{"type":"deleteMessage","messageID":10,"chat_id":8,"last_message":{"id":9,"chat_id":8}}
{"type":"reactions","msgID":10,"chat":{"id":8,"chat_id":8},"reactions":[]}
{"type":"messageState","chat_id":8,"message_ids":[10],"state":2,"target_state":2}

For the reactions socket variant, chat.id is overwritten with the conversation ID by the sender; use msgID for the reacted message. A deleted conversation's preview can be a fallback message when no surviving message exists.

Working sequence and verification

// Example for an integration using socket.io-client.
const socket = io('https://socket.example.com', {
  transports: ['websocket'], autoConnect: false
});
socket.on('connect', () => socket.emit('conn', {
  token: session.token, apiKey: API_KEY, prefix: 'tomchat'
}));
socket.on('appCon', async (value) => {
  if (value !== 1) return;
  // POST /api/live/enterRoom with Auth-Token and {rid:7,password:...}.
  // Require code=200 AND data.state="ok" before joining Agora.
});
socket.on('roomSeats', seats => renderSeats(seats));
socket.on('roomMessage', message => appendMessage(message));
socket.on('roomGift', gifts => renderGifts(gifts));
socket.on('forceLogout', () => { socket.disconnect(); clearSession(); });
socket.connect();
  1. Sign in through PHP. Register listeners before calling socket.connect.
  2. Wait for appCon=1, then enter the room through PHP. Node receives the Redis event and joins the socket to that room.
  3. POST live/seatTake, live/sendMessage or live/sendGift; check the PHP outcome, then observe roomSeats, roomMessage or roomGift on a second client.
  4. To leave, POST live/leaveRoom then emit leaveRoom with the same rid. Release Agora locally.
  5. On reconnect, reauthenticate conn and refresh authoritative PHP state. Re-enter only after appCon. Do not replay purchases/gifts.

Source map: node_server/s1.js and src/handlers/user.js define routing and direct handlers; PHP LiveAppController, RoomAppController, ChatAppController, LiveboxAppController, CashAppController and AuthAppController publish business events; AdminRoomClosureService publishes stopRoom. Flutter's forceReconnect/reconnect are local event-emitter signals, not server catalogue entries.

Disconnect recovery

The last socket disconnect schedules room cleanup after 60 seconds. Entering the same room through PHP startLive or enterRoom cancels its Redis job; socket reauthentication or entering another room preserves it. See shared-secret configuration and callback protection.
