Socket host, port and transport scheme

The delivered SocketManager constructs http://$ip:$port. Port 443 alone does not select HTTPS. For a TLS-only socket proxy, update that URL construction to HTTPS and verify the release app on a device. There is no scheme key in AppChatConfig. Follow the socket transport notes; do not assume the build command below fixes this source limitation.

Every AppChatConfig key

The buyer configuration file is flutter_app/lib/config/appchat_config.dart. These five values are compile-time constants. --dart-define overrides the source default for that build; it is not a runtime .env file. A hot reload or backend-only edit does not change the compiled value.

Set, build, then verify

Run inside flutter_app. The following is a macOS/Linux shell example; in PowerShell put the command on one line or use PowerShell continuation syntax.

flutter build appbundle --release \
  --dart-define=TOMCHAT_API_BASE_URL=https://api.example.com/ \
  --dart-define=TOMCHAT_API_KEY=YOUR_SHARED_APP_KEY \
  --dart-define=TOMCHAT_SOCKET_HOST=socket.example.com \
  --dart-define=TOMCHAT_SOCKET_PORT=443 \
  --dart-define=TOMCHAT_SHARE_BASE_URL=https://example.com/share
  1. Set PHP SOCKET_IP/SOCKET_PORT to the same public destination. The auth response is authoritative when present; changing only the Dart fallback may appear to do nothing.
  2. Install the newly built app and sign in again.
  3. Confirm the requested API hostname in development logs, helper/config response and session socket values.
  4. Verify appCon=1, enter a room, exchange a message between two devices, then open a shared profile/room link.

Configuration outside this file

These are platform/service setup values, not AppChatConfig keys.

  • Firebase: supply your android/app/google-services.json, ios/Runner/GoogleService-Info.plist and generated lib/firebase_options.dart. Google sign-in requires the correct Android fingerprints and iOS URL scheme.
  • Android: applicationId/namespace in android/app/build.gradle.kts, app label and release keystore configuration.
  • iOS: Runner bundle identifier, development team, signing/provisioning, capabilities, privacy purpose strings and version/build number. See the iOS release guide.
  • Agora: app ID comes from helper/config; the certificate stays on PHP. Channel tokens come from room entry responses.
  • Purchases: product IDs in recharge_packages must match the products in the buyer's own Play Console/App Store Connect account.
  • Branding/legal URLs: update the app logo, displayed name, and privacy/terms/support destinations in the relevant screen/helper files before release.

Backend DB, Redis, Firebase Admin, billing verification and Bunny credentials belong in backend .env/service-account files, never in this Dart class. Consult the Environment Files and service setup sections in index.html.
